# PandasConform — reproduction artifact

This directory contains a self-contained reproduction workspace for PandasConform.

## Contents

| Path | Purpose |
|---|---|
| `06_pandas_conformance/src/` | Implementation and experiment libraries |
| `06_pandas_conformance/tests/` | Correctness and regression checks |
| `06_pandas_conformance/results/` | Saved measurements and derived results |
| `tools/` | Shared resource supervisors and plotting utilities |
| `setup.sh` | Create the Python environment from recorded dependencies |
| `reproduce.sh` | Run the default saved-result analysis, tests, or a chosen driver |
| `MANIFEST.json`, `verify.py` | File sizes, SHA-256 hashes, and integrity checking |

## Quick start

Use Python 3.12, uv, and a POSIX shell. The native measurements were collected on Apple Silicon macOS; CPU-only analyses can also run on compatible environments.

```bash
python3 verify.py --full
bash setup.sh
bash reproduce.sh analysis
bash reproduce.sh test
```

`test` runs the core checks. `test-all` runs the complete included suite and can require native services or engine environments. Use `bash guarded_run.sh run <driver.py> [arguments]` for a supervised fresh experiment.

Run these commands from this directory. `setup.sh` installs the recorded environment; network access is needed for dependency installation. `ARTIFACT_PYTHON=/absolute/path/to/python` can select an existing compatible interpreter for the reproduction launcher. Relative paths are resolved inside the bundled source directory. Analyses can update derived outputs; use a fresh copy to repeat integrity verification against the original inventory.

## Data and full experiments

The bundle contains the harness, comparator, notebook code and selection manifests, input-file hashes, per-engine dependency locks, probes and minimized reproducers, saved run/classification records, and the compact Round 5 replay/capture evidence. The default analysis rebuilds dataset-group and evidence summaries without downloading the large corpus.

Reconstruct the public corpus and isolated engine environments from the source directory:

```bash
PY=../.venv/bin/python bash scripts/get_pandasbench.sh
bash ../setup_engines.sh ref p15 p30 modin fireducks bodo dask
```

The pinned upstream commit is recorded in `data/PandasBench/.artifact_commit`; the input archive checksum and per-file hashes are in `data/raw/PandasBench_data.zip.sha256` and `data/provenance.json`. The upstream archive is about 12 GB and expands to about 59 GB. Full scaled inputs and column captures are generated by the harness, so reserve additional disk space. Existing aggregate classifications support the bundled analyses; fresh cell comparisons require regenerated captures.

A small fresh reference campaign, followed by comparison, can be started with:

```bash
bash reproduce.sh run -m pconf.orchestrate run --campaign reproduced_smoke --set pilot --engines ref,ref#2,pyarrow_backend --scale 1 --limit 1
bash reproduce.sh run -m pconf.orchestrate compare --campaign reproduced_smoke --set pilot --engines pyarrow_backend --ref2 'ref#2'
```

The full campaign grids and CPU budgets are in `scripts/steps_*.json`, `scripts/batch.py`, and `src/pconf/engines.py`. `requirements/<engine>.txt` pins each environment; pandas 1.5 uses Python 3.11 and the other engine environments use Python 3.12. Engine availability depends on the target OS and architecture. Resource limits, fallback flags, and conversion semantics are retained in the configurations and saved metadata.

## Resources and outputs

The default analysis uses saved measurements. Full experiments can require local models, native services, significant disk space, and hours of compute. Run one heavy campaign at a time. The supervisors in `tools/` preserve the original process-memory ceiling of 200 GB and host ceiling of 490 GB; select a smaller job limit for smaller machines. Saved timing values describe the measured hardware. Replays preserve the recorded seeds, configurations, and input identities; fresh concurrent or model-server timing measurements can vary.

The source directory retains its original experiment and result paths. New experiments should use separate output directories where the driver supports them. Dependency locks, source revisions, input hashes, model identifiers, and run metadata are retained alongside the corresponding measurements.

## Clone and retrieve data

Large data files use Git LFS. Install Git LFS before cloning, then retrieve all data objects:

```bash
git lfs install
git clone https://github.com/LeoTTTPhat/PandasConform.git
cd PandasConform
git lfs pull
python3 verify.py --full
```
